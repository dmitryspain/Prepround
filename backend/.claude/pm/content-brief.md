# Бриф контенту: автор і фактчек у хвилях

Вижимка з ADR 002 (формат), ADR 004 (джерела, рубрика, чекліст, версії) і CLAUDE.md для `content-author` і `tester` у **хвилях** (рішення власника 2026-11-17). У хвилі читаєш цей файл **замість** CLAUDE.md, ADR 002 і ADR 004. Повні документи відкривай лише тоді, коли бриф чогось не покриває. Якщо бриф і ADR розходяться, правильний ADR, а розбіжність опиши у звіті.

Шляхи в брифі відносно кореня репо `Prepround/`, а команди запускаються з `Prepround/backend`.

## Файл теми

`content/it/topics/<тема>.yaml`. Порожня тема має `questions: []`.

**Чернетка (PRP-023, ADR 005, розділ 6).** Тема без PASS фактчеку має на верхньому рівні рядок `draft: true` після `description`. Прод-імпорт її питань не бере. Автор рядок `draft` не знімає і не видаляє. Нову тему (новий файл) автор створює одразу з `draft: true`. Знімає позначку лише головна сесія, після PASS.

```yaml
  - id: <тема>-NNN          # наступний після максимального; id не змінюємо й не перевикористовуємо
    level: junior            # id рівня зі шкали content/it/field.yaml
    type: single             # single — рівно 1 правильний; multiple — ≥ 2 правильних і ≥ 1 хибний
    text: Що виведе цей код (Python 3.14)?
    code:                    # необов'язково
      lang: python
      source: |
        print(1 if [] else 2)
    options:                 # 4–5 варіантів, тексти в межах питання не повторюються
      - text: '`2`'
        correct: true
      - text: '`1`'
      - text: '`None`'
      - text: '`TypeError`'
    explanation: >           # 1–4 речення: чому правильна відповідь правильна і чому найспокусливіший дистрактор хибний
      Порожній список хибний у булевому контексті, тому …
    sources:                 # для нових питань обов'язково: 1–2 https-URL, бажано з #якорем
      - https://docs.python.org/3/library/stdtypes.html#truth-value-testing
```

- Відступи: `  - id:` (2 пробіли), `code:` (4). Файл редагуй як текст, не через `yaml.dump`.
- Невідомий ключ (`corect`) — помилка. Inline-код пиши в бектиках. Markdown не підтримується. Базова мова — українська; англійська — див. «Дві мови».

## Дві мови (ADR 006; діє після PRP-029, до того ключів `_en` не пиши)

- **Нове питання пишеш одразу двома мовами:**
  - `text_en` — одразу після `text`;
  - `text_en` у кожному варіанті — після його `text`, перед `correct`;
  - `explanation_en` — після `explanation`.
- **Нова тема** має також `title_en` і `description_en`. Формат і правила перекладу описано в `backend/.claude/pm/translation-brief.md`, розділи «Що робиш» і «Як перекладати».
- **`code` спільний для мов.** Коментарі в коді пиши англійською. Рядкові літерали пиши так, як потрібно для питання.
- **Правиш опубліковане питання — правиш обидві мови.** `content-lint … --base <знімок>` ловить українську правку без англійської.
- **Лінт перевіряє англійську так само:** довжини варіантів, «all of the above», кирилицю поза бектиками, inline-код варіантів, повноту перекладу теми.

## Рубрика складності

| Рівень | Що перевіряє | Типова форма |
|---|---|---|
| `junior` | що це і як цим користуватися; одна концепція | «Що гарантує…», «Що виведе…» на 3–6 рядках коду без пасток |
| `middle` | чому так і що станеться в щоденному, але нетривіальному сценарії; взаємодія двох концепцій | передбачити результат коду або знайти проблему; «чому не працює…» |
| `senior` | межі, компроміси, діагностика: конкурентність, пам'ять, транзакції, внутрішня механіка, вибір за обмежень, симптоми в продакшні | сценарій з обмеженнями → що станеться, що вибрати і чому |

Складність має йти від розуміння, а не від пам'яті. Рівня **не** підвищують: рідкісна назва API чи прапорця, номер версії, значення за замовчуванням, яке ніхто не пам'ятає, двозначне формулювання-пастка.

## Чекліст якості

1. **Однозначність.** У `single` одна відповідь, яку можна захистити посиланням, у `multiple` — точна множина. Формулювань на кшталт «найкращий спосіб» без критерію немає. Якщо відповідь залежить від версії, версія вказана в тексті.
2. **Дистрактори** — типові хибні уявлення того самого стилю й довжини, без «усе з переліченого» і «жодне».
3. **Баланс у темі:** рівні порівну (4/4/4), `multiple` 25–40 % (3–4 з 12), блок `code` ≥ 25 % у мовних темах. У спільних темах (★ у spec 4.1) код нейтральний щодо стеку: SQL, YAML, Dockerfile, псевдокод.
4. **Межі тем і дублікати.** Одна концепція — не більше одного питання на рівень у темі. Межі задає колонка «Покриває» spec 4.2. Читай лише рядки своїх тем: `grep -E '^\| \`(тема1|тема2)\`' .claude/pm/spec.md`. Перед написанням переглянь наявні питання теми й суміжних: `grep -h '^    text:' ../content/it/topics/<тема>.yaml`.
5. **Сумнів.** Факт, який не вдалося підтвердити джерелом чи запуском, у питання не потрапляє.
6. **Пояснення без звітів про власну перевірку** («я перевірив запуском», «у тесті вийшло…», «запуском отримано…»): користувач бачить пояснення без контексту автора. Докази — у звіті, а не в YAML (урок хвилі 3: такі фрази знайшлися в 5 темах).
7. **Умова питання повна.** Якщо відповідь залежить від налаштування, якого немає в коді (`$fillable`, `--tries`, рівень ізоляції, версія), воно названо в тексті (уроки `laravel-010`, `php-orm-006`).

Пункти 2 і 3, довжини варіантів, `sources` і живі URL механічно перевіряє `content-lint` (див. «Команди»). Тобі лишаються факти, рівні й межі тем.

## Джерела

- **Пріоритет:** офіційна документація продукту → специфікація (ECMA-262, RFC, PEP) → офіційний блог розробників продукту. Для тем без продукту — Azure Architecture Center, .NET Architecture Guides і першоджерело автора концепції (martinfowler.com, microservices.io), але лише як факт.
- **Не є джерелом:** Stack Overflow, Medium, особисті блоги, відповідь AI.
- **URL:** learn.microsoft.com — з `/en-us/`; PostgreSQL — `/docs/18/`, а не `/docs/current/`; Prisma — `prisma.io/docs/orm/v7/…`, бо без `/v7/` сторінки вже описують наступну версію (Prisma Next); Laravel — `laravel.com/docs/13.x/…`. Сторінка має підтверджувати саме правильну відповідь.
- **Точкова звірка.** Сторінку цілком не читай. Шукай `curl -sL -A 'Mozilla/5.0' "<url>" | sed 's/<[^>]*>//g' | grep -i -m3 -C2 '<ключове слово>'` або вузьким запитом WebFetch («Чи сказано, що X? Процитуй одне речення»).

## Запуск коду

Перевіряй запуском, коли відповідь залежить від виводу коду.

| Мова | Як запускати |
|---|---|
| C# | локально `dotnet run <файл>.cs` |
| SQL | `docker exec prepround-postgres psql -U prepround -d postgres …` (тимчасові таблиці або `BEGIN … ROLLBACK`), **ніколи** не в БД `prepround` |
| Python | `docker run --rm -v "$PWD":/w -w /w python:3.14 python main.py` (локальний 3.12 застарий) |
| JS / TS / Node | `docker run --rm -v "$PWD":/w -w /w node:24-alpine node main.js` (локальний 22 застарий); `.ts` Node 24 запускає напряму |
| Java | `docker run --rm -v "$PWD":/w -w /w eclipse-temurin:25 java Main.java` |
| Go | `docker run --rm -v "$PWD":/w -w /w golang:1.27-alpine go run main.go` (локальний `go` 1.26 — лише для того, що не змінилось у 1.27); модулі (`go get`) — усередині контейнера |
| Frontend (Angular, React, Vue) | `node:24-alpine` у `docker run --rm`, пакети — `npm i` усередині. Бери найлегший спосіб: логіку без DOM (signals `signal`/`computed`/`effect`, RxJS, стори Pinia/Zustand/RTK, `vue` `ref`/`computed`/`watch`) — просто `node main.mjs`; рендер React — `react-dom/server` (`renderToString`) або Testing Library + `jsdom` у Vitest; Vue — `@vue/test-utils` + `jsdom` або `vue/server-renderer`; Angular-компоненти — `TestBed` у мінімальному проєкті: Vitest + `jsdom` + `@analogjs/vite-plugin-angular` (перевірено на Angular 22.2). Повний `ng new` / `create-next-app` / `nuxi init` — лише якщо інакше не перевірити. `node_modules` після теми видаляй обов'язково: він важить сотні мегабайт |
| PHP | `docker run --rm -v "$PWD":/w -w /w php:8.5-cli php main.php`. Composer (Laravel, Symfony, Doctrine, PHPUnit) став у тому ж контейнері: `curl -sS https://getcomposer.org/installer \| php -- --install-dir=/usr/local/bin --filename=composer`, потім `composer require …`. Потрібні `git` і `unzip` (`apt-get update && apt-get install -y git unzip`) |

- **Образи — лише з цієї таблиці**, їх заздалегідь тягне головна сесія. Ти не робиш `docker pull` чи `docker build` і не запускаєш інші образи: колись диск заповнився і Docker завис. Якщо потрібного рантайму немає, перевір за джерелом і напиши це у звіті.
- **Чого не запускаємо:** брокери, кластери, сторонні сервіси. Таке перевіряй за джерелом.
- **Тимчасові файли** (код, виводи, скрипти) — лише в теці теми в scratchpad, **ніколи** в `/tmp`: прибрати там за собою агент не має права.
- **Прибирання:** контейнери лише з `--rm`. Пакети (`pip install`, `npm i`) став усередині контейнера. Після теми видали `node_modules`, `.venv` і кеші з теки теми в scratchpad.

## Команди (з `Prepround/backend`)

- `dotnet run --no-build --project src/Prepround.ContentTool -- validate ../content; echo $?` → `0`. Дивись лише на свої файли. `--no-build` обов'язковий: кілька агентів, які одночасно збирають той самий проєкт, ламають збірку один одному. Код у хвилях не змінюється, а зібрала його головна сесія.
- `python3 .claude/tools/content-lint.py <тема> [<тема> …] --urls; echo $?` → `0`. Скрипт перевіряє:
  - баланс рівнів, частку `multiple` і `code`;
  - довжини варіантів: правильна найдовша щонайбільше в 5 з 9 `single`, але хоча б в 1, і не більш ніж у 1,2 раза довша за найдовший дистрактор; у `multiple` середні довжини правильних і хибних у межах 0,83–1,2;
  - «усе з переліченого», наявність `sources`, HTTP 2xx для кожного URL.

  Рядки `!` — підозра на дубль; глянь і виріши. Довжини виправляй, не чіпаючи фактів: подробиці переноси в `explanation`, дистракторам додай конкретних правдоподібних деталей. **Пастка (урок 2026-11-17, `sql-010`):** не додавай до дистрактора причин, умов чи уточнень, бо хибний варіант легко стає правдивим, а `multiple` — двозначним. Безпечніше вкоротити правильний варіант або подовжити дистрактор деталями його ж хибної ідеї.
- `import` і `dotnet test` у хвилі запускає лише головна сесія.

## Фактчек хвилі (tester)

1. `content-lint <теми> --urls` → `0`, інакше FAIL з переліком рядків `✗`.
2. Запуском — усі питання, де відповідь залежить від виводу коду.
3. `senior` і `multiple` — щонайменше половина, за сторінкою з `sources`.
4. Решта — щонайменше 15 %, за джерелом.
5. Будь-яка хибна «правильна» відповідь — `critical`. Тоді повна перевірка цієї теми і FAIL для неї.
   - **Після PRP-029:** англійську читаєш поруч для **кожного** питання за чеклістом `translation-brief.md`, розділ «Перевірка перекладу», п. 2–3. Якщо множина правильних варіантів англійською інша, це теж `critical`.
6. Контент tester не править. Пункти для автора йдуть у секцію «Для кодера» з id питання, що не так і доказом (URL або вивід запуску).
