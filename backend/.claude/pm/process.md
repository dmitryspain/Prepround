# Процес головної сесії

Цей файл читає лише головна сесія (субагенти отримують `CLAUDE.md` і своє визначення). Перенесено з `CLAUDE.md` 2026-11-26, щоб не роздувати контекст кожного агента.

## Економія токенів (рішення власника 2026-11-26)

Дослідження 2026-11-26: за 11 днів одна сесія спалила ~95 млн «умовних» токенів. 39 % — сама головна сесія (контекст на запит у медіані 335 тис., наприкінці 740 тис.), 33 % — tester на Opus, 11 % — coder, 11 % — автори, 5 % — PM. Правила:

1. **Нова сесія на етап або пакет карток.** Після закриття етапу, після ~5 карток або коли контекст розрісся, головна сесія дописує стан у «Готовність карток» і пише власнику: «Почнімо нову сесію (`/clear`), стан у беклозі». Увесь стан — у беклозі, git і файлах звітів, не в контексті.
2. **Передача між агентами — файлами, не текстом у промпті.** Картку головна сесія вирізає у `backend/.claude/reports/PRP-NNN-card.md` (`sed -n '/^### PRP-NNN/,/^### PRP-/p' … | sed '$d'`), звіт агента лежить у `backend/.claude/reports/PRP-NNN-<роль>.md`. У промпт іде лише шлях і 2–5 рядків приміток. Дослівно в промпт нічого не копіюємо.
3. **Відповіді агентів — короткі** (див. `CLAUDE.md`, «Агенти й звіти»). Повний звіт головна сесія читає з файлу лише тоді, коли без нього не вирішити (наприклад, щоб розкласти хвости).
4. **До 3 агентів одночасно.** Більше паралелі не зменшує сумарну витрату, а лише швидше вичерпує 5-годинне вікно.
5. **Модель за типом роботи** (параметр `model` у виклику Agent):
   - `content-author` — `sonnet`;
   - `tester` перекладу й стилю (хвилі перекладу) — `sonnet`;
   - `tester` карток із кодом і фактчеку контенту, `coder`, `project-manager` — модель сесії (Opus).
6. **Не читати великі файли цілком.** `backlog.md` — через `grep -n` і `sed -n` по картці; виконані картки переносити в `backlog-archive.md` на закритті етапу. Те саме з `knowledge.md` і `spec.md`.
7. **Дрібні механічні кроки групувати** в одну команду (лінт кількох тем, зняття `draft_en`, коміт), а не робити окремими викликами: кожен виклик головної сесії перечитує весь її контекст.
8. **Effort:** для рутинної оркестрації власник тримає `/effort high`; `xhigh` — лише для складних рішень.

## «Погнали»

Коли власник пише «погнали» («далі», «продовжуй»), головна сесія сама веде цикл агентів і зайвого не перепитує. Нахил на розробку (рішення 2026-11-14): PM не закриває кожну картку, tester перевіряє пропорційно (`tester.md`, «Обсяг перевірки»).

1. Прочитай «Готовність карток» на початку `backlog.md` (`sed -n '1,60p'`).
2. Візьми першу картку з «Готово для coder зараз». Немає такої або блок не відповідає статусам — виклич `project-manager` у режимі «що далі?». Перед карткою `frontend` у новій сесії перевір запис у `PreproundWeb` пробним файлом.
3. Виріж картку у файл (див. «Економія», п. 2) і передай виконавцю з поля «Виконавець» шлях до неї, шлях для звіту і примітки головної сесії (хвости попередніх карток). Потім `tester`: шлях до картки, шлях до звіту виконавця, шлях для свого звіту.
4. `FAIL` → виконавцю (через `SendMessage`, контекст збережено) шлях до звіту tester і номери пунктів «Для кодера»; далі той самий tester. Максимум 3 кола.
5. `PASS` → закрий картку **сама**: у `backlog.md` статус `done`, «**Результат (дата):** PASS з N кола; тести: total X / failed 0», «**Хвости:**» (з «Помічено поза скоупом» coder і «Зауваження» tester — стисло, з посиланням на файл звіту); онови «Готовність»; хвіст до наступної картки — приміткою; змінились команди чи структура — онови `CLAUDE.md`. Закоміть і запуш (розділ «Git»).
6. `project-manager` — лише на закритті етапу, після 3 невдалих кіл, коли хвіст змінює план/spec/контракт або «Готовність» порожня.
7. Картки — **послідовно** (одна команда на два репо).

Зупинись і коротко напиши власнику, коли: наступна картка «Виконавець: власник» або заблокована його кроком; картка не пройшла за 3 кола; агент повернув питання, без якого не рухатись; закінчився етап. Між картками — один рядок «PRP-NNN: PASS, беру PRP-MMM».

## Хвилі контенту й перекладу

- **Автор:** один запуск — одна тема, `model: "sonnet"`, читає бриф (`pm/content-brief.md` або `pm/translation-brief.md`) замість ADR. Без `import` і `dotnet test`. ContentTool — лише `--no-build`.
- **Автор здав тему** → `content-lint <тема> [--urls]` (у перекладі — `--base <знімок> --translation-only`); `✗` — тому самому автору через `SendMessage`. Чиста тема — в чергу tester.
- **Tester** бере 2–4 теми одного стеку. Перед ним на групу: `validate` → `import --include-drafts` → `dotnet test` **на замороженій копії** (`cp -R ../content <scratchpad>/snap`, `PREPROUND_TEST_CONTENT_DIR=<snap>`), бо автори паралельно пишуть `content/`.
- **Правки після PASS:** tester дає готові копії файлів із правками, перевірені лінтом; головна сесія звіряє `diff` (лише `*_en`/зміст) і копіює, без нового кола автора.
- `FAIL` у темі → автору пункти, далі той самий tester (до 3 кіл); решта хвилі не чекає.
- **Чернетки (PRP-023):** нова тема одразу з `draft: true`, знімає головна сесія після PASS; переклад — `draft_en: true` до PASS. Імпорти хвиль у dev-БД — з `--include-drafts`; прод-імпорт — без прапорця.
- **Знімок бази перекладу:** `rm -rf <base> && cp -R ../content <base>` (інакше копія вкладеться всередину). Якщо знімок пошкоджено — відновити з git (`git archive <коміт> content`). `--translation-only` — завжди разом з `validate`.
- **Дві мови (з PRP-029):** нові питання пишуться одразу uk+en; фікси опублікованих тем — `content-lint … --base <знімок до фіксу>`.
- **Docker для авторів:** лише образи з таблиці брифу; перед хвилею головна сесія тягне відсутні й перевіряє `docker run --rm <образ> <версія>`; після — прибирає нові.
- Зупинка — коли закінчилась черга напряму або на `critical`, повтореному в другому колі.

## Деплой (ADR 005)

| Що | Де |
|---|---|
| Фронт | https://prepround.pages.dev — Cloudflare Pages, проєкт `prepround`, репо `dmitryspain/PreproundUI`, `master`, `npm run build`, `dist/web/browser` |
| API | https://prepround-api.onrender.com — Render Free, `prepround-api`, репо `dmitryspain/Prepround`, Docker, Root `backend`, health `/api/health` |
| БД | Neon Free, Frankfurt, PG 18, БД `preprounddb`; `preprounddb_owner` — міграції й імпорт, `prepround_reader` (лише `SELECT`) — API |

- Push у `master` перезбирає обидва сервіси. Єдиний секрет — змінна Render `ConnectionStrings__Prepround` (роль читача).
- **Міграції:** нову EF-міграцію застосувати в Neon **до** push коду, що від неї залежить. Або з `prod.env` (див. «Прод-імпорт»), або: `dotnet ef migrations script <від> <до> --idempotent` і виконати в Neon SQL Editor (роль `preprounddb_owner`, Chrome — з дозволу власника).
- **Прод-імпорт** (рішення власника 2026-11-28): рядок ролі `preprounddb_owner` лежить у `~/.config/prepround/prod.env` (поза репо, `600`), рядок у чаті більше не потрібен. Головна сесія запускає сама з закоміченого стану, без `--include-drafts`: `set -a; source ~/.config/prepround/prod.env; set +a; dotnet run --no-build --project src/Prepround.ContentTool -- import ../content` (поза пісочницею); після — smoke `curl` каталогу (`?lang=en` теж). У user-secrets не класти: локальний `import` пішов би в прод. Субагентам цей файл не давати. Файл зник або пароль змінено — рядок у Neon Console → Connect (Npgsql не приймає URI: `Host=…;Database=…;Username=…;Password=…;SSL Mode=VerifyFull;Channel Binding=Require;GSS Encryption Mode=Disable`).
- **Холодний старт:** Render засинає після 15 хв; пробудження ~25 с (Render 14 с + перший запит до БД 11 с).

## Git (з 2026-11-21 комітить і пушить головна сесія)

- Після закриття картки чи теми — коміт у `master` відповідного репо (міжрепозиторна картка — в обидва з тим самим `PRP-NNN`). Повідомлення англійською, з рядком Co-Authored-By.
- **Push лише через SSH** (HTTPS-облікові дані сесії недоступні): `git push git@github.com:dmitryspain/Prepround.git master`, `git push git@github.com:dmitryspain/PreproundUI.git master`, поза пісочницею; потім `git update-ref refs/remotes/origin/master HEAD`.
- Не пушити: `backend/` з міграцією, не застосованою в Neon; файли, які ще правлять агенти; секрети.

## Довідка: iOS (відкладено, PRP-008)

Capacitor 8 у `PreproundWeb/ios/`, Bundle ID `io.github.dmitryspain.prepround`. Збірка `mobile` → `dist/mobile` (`webDir`), адреса API — `environment.mobile.ts`; платформні відмінності — `core/platform.ts` і `html[data-native]`; CORS має містити `capacitor://localhost`; підпис — Personal Team (7 днів, до 3 застосунків). Симулятор на Xcode 27 — DeviceHub, запуск через `xcrun simctl launch`. Команди: `npm run build:mobile`, `npm run ios:sync`, `xcodebuild … -sdk iphonesimulator … CODE_SIGNING_ALLOWED=NO build`.
