## Обсяг перевірки (рішення власника 2026-11-14)

Власник хоче, щоб більшу частину часу займала розробка. Тому перевіряй пропорційно: перевірка має тривати помітно менше, ніж розробка картки.

- **Обов'язково:**
  - кожен критерій приймання доведено командою або тестом;
  - тести на нову поведінку й на ризики з розділу «Для tester» картки;
  - повний прогін наявних тестів;
  - **фактична правильність контенту** — без послаблень (див. процес, п. 3).
- **Мутаційна перевірка** — лише для ключової логіки: вибір питань, розподіл, оцінювання, таймер, валідація контенту. Досить 1–3 мутацій на картку. Для каркасу, конфігів, DI і тонких контролерів не роби.
- **Не роби:**
  - масового ручного перебору поломок понад критерії (десятки варіантів YAML тощо);
  - тестів на поведінку, яку вже покривають наявні тести або фреймворк;
  - окремих тимчасових контейнерів і проєктів, якщо критерій цього не вимагає. Для інтеграційних тестів досить Testcontainers.
- Сумнівний, але не критичний ризик запиши в «Зауваження (не блокує)», а не досліджуй до кінця.

## Вердикти

- **PASS:** кожен критерій доведено тестом або командою, усі тести зелені.
- **FAIL:** є баг, невиконаний критерій, розбіжність зі spec, регресія або фактична помилка в контенті.
- **BLOCKED:** перевірити неможливо (немає середовища, критерій незрозумілий). Поясни, чого бракує. Картку з платформою `ios` без Xcode і симулятора перевірити неможливо, це теж BLOCKED.

Дрібниці стилю не є причиною для FAIL. Записуй їх у «Зауваження (не блокує)».

## Формат звіту (обов'язковий)

**Куди писати звіт (рішення власника 2026-11-26, економія токенів).** Повний звіт у форматі нижче запиши у файл, який назвала головна сесія (за замовчуванням `backend/.claude/reports/<PRP-або-тема>-tester.md`). Головній сесії відповідай **коротко, до ~15 рядків**: вердикт, рядок «Прогін», при FAIL — пункти «Для кодера» стисло (id, поле/файл, суть), а для PASS із правками — шлях до копії файлів із правками і шлях до повного звіту. Довгих таблиць, логів і повторення картки у відповіді не треба.

```
## Звіт tester · PRP-NNN — PASS | FAIL | BLOCKED
**Критерії приймання:**
- [x] критерій — чим доведено (тест / команда з виводом)
- [ ] критерій — чому не виконано
**Додані/змінені тести:** `Prepround/…` або `PreproundWeb/…` — що покривають
**Прогін:** dotnet test → N passed, M failed · validate → exit … · ng test → … · iOS (симулятор) → … (або «не запускався: причина»)

### Для кодера (тільки при FAIL)
1. [critical|major|minor] `файл:рядок` — що не так. Відтворення: … Очікувано: … Фактично: …
2. …

**Зауваження (не блокує):** …
```

Кожен пункт «Для кодера» має бути самодостатнім: coder не бачить твоїх міркувань, тільки цей список.
